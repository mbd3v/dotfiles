= How to install

Clone the repo and run the setup script:

----
git clone git@github.com:mbd3v/dotfiles.git $HOME/.dot_cfg
$HOME/.dot_cfg/setup.sh
----

`setup.sh` symlinks each managed path from `$HOME` into the repo. `~/.config/nvim`
is linked as a whole directory, so new nvim files show up in `git status` with no
extra step. Anything already at a target path is moved to `<path>.bak.<timestamp>`
first. Running it again is safe.

To add a file, move it into the repo, add its path to the `links` list at the top
of `setup.sh`, and rerun the script. If the repo path differs from the home path,
write the entry as `repo_path:home_path`.

Claude Code skills and settings live in `claude/` and link into `~/.claude/`. The
repo copy isn't called `.claude/`, because Claude Code would load it as project
config whenever a session starts in this repo. To add a skill, move
`~/.claude/skills/<name>` to `claude/skills/<name>` and add
`claude/skills/<name>:.claude/skills/<name>` to `links`. `~/.claude/skills/synced`
belongs to claude.ai and stays out of the repo.

Some tools replace a symlink with a regular file when they save. Run
`setup.sh --check` to list any managed path that is no longer linked, copy its
contents back into the repo if needed, and rerun `setup.sh`.

`setup.sh --root` copies the same files into `/root`. Root gets copies instead of
links so root's nvim can't write root-owned files into the repo. Rerun it after
changes you want root to have.

The `dotfile_config` alias in `.zshrc` runs git against this repo from any
directory, e.g. `dotfile_config status`.

Instructions for configuring Tmux are found in the .tmux.conf file.
